## 2. Цели и назначение ПО

### 2.1 Назначение ПО

ПО предназначено для автоматизации полного цикла подготовки аналитического отчёта:

1. приём параметров отчёта от пользователя через графический интерфейс;
2. формирование набора данных за выбранный период;
3. генерация аналитического вывода с помощью языковой модели;
4. компоновка отчёта на отдельном листе Google Таблицы;
5. автоматическое оформление листа (цвета, шрифты, объединения, границы, числовые форматы, диаграмма);
6. выдача пользователю ссылки на готовый отчёт.

Модуль `google_sheets.py` дополнительно предназначен для повторного использования в любых других приложениях как самостоятельная библиотека работы с Google Таблицами.

### 2.2 Цели ПО

| Цель | Измеримый результат |
|---|---|
| Сократить время подготовки отчёта | С 20–40 минут ручной работы до не более 1 минуты. |
| Исключить ручное форматирование | 100% отчётов оформляются по единому шаблону автоматически. |
| Обеспечить единый корпоративный стиль | Все отчёты используют одну палитру, шрифты и структуру блоков. |
| Автоматизировать аналитический вывод | Текст объёмом 5–7 предложений формируется ИИ на основе данных отчёта. |
| Обеспечить повторное использование | Модуль `google_sheets.py` подключается в сторонние Python-приложения без изменения кода. |
| Снизить количество ошибок ввода | Валидация параметров до начала генерации. |

#### 3.1.1 Подключение к Google Sheets (F-01)

- **Входные данные:** путь к JSON-ключу сервисного аккаунта, Spreadsheet ID, перечень scopes.
- **Поведение:** модуль создаёт объект авторизации на основе сервисного аккаунта и инициализирует клиенты `gspread`-совместимого уровня — `googleapiclient.discovery.build('sheets', 'v4')`. При успешном подключении возвращаются метаданные таблицы: название, список листов, URL.
- **Scopes:** `https://www.googleapis.com/auth/spreadsheets` (чтение и запись). Расширенные права не запрашиваются.
- **Ошибки:** отсутствие файла ключа, некорректный JSON, отсутствие доступа к таблице, истёкший или отозванный ключ. Каждая ошибка сопровождается понятным сообщением на русском языке и записью в журнал.
- **Критерий приёмки:** при корректных настройках подключение выполняется без участия пользователя и занимает не более 3 секунд.

#### 3.1.2 CRUD-операции (F-02)

Модуль `google_sheets.py` обязан предоставлять следующие операции:

| Операция | Метод | Описание |
|---|---|---|
| Create | `create_sheet(title)` | Создание листа; возвращает его `sheetId`. |
| Create | `append_rows(sheet, rows)` | Добавление строк в конец таблицы. |
| Read | `read_all(sheet=None)` | Чтение всех ячеек листа (или всех листов). |
| Read | `read_range(a1_range)` | Чтение произвольного диапазона A1. |
| Read | `list_sheets()` | Список названий листов. |
| Update | `update_range(a1_range, values)` | Запись значений в диапазон. |
| Update | `batch_format(sheet_id, requests)` | Пакетное применение форматирования. |
| Delete | `clear_range(a1_range)` | Очистка значений диапазона. |
| Delete | `delete_rows(sheet, start_index, count)` | Удаление строк. |
| Delete | `delete_sheet(title)` | Удаление листа. |

Требования к реализации:

- класс оформляется в ООП-стиле, состояние подключения инкапсулировано;
- публичные методы не зависят от tkinter и не содержат кода интерфейса;
- все методы документированы docstring-описаниями;
- ошибки API преобразуются в собственные исключения модуля (`SheetsConnectionError`, `SheetsOperationError`).

#### 3.1.3 Самопроверка модуля (F-03)

При запуске `python google_sheets.py` выполняется точка входа:

1. загружаются настройки из `.env`;
2. выполняется подключение к таблице;
3. читаются все ячейки первого листа (или листа, указанного в параметре);
4. содержимое выводится в консоль в табличном виде с разделителями;
5. выводится количество прочитанных строк, столбцов и ссылка на таблицу.

При ошибке подключения выводится диагностическое сообщение и код возврата `1`.

#### 3.1.4 Генерация случайных данных (F-04)

- **Входные данные:** тип отчёта, период (дата начала и окончания), подразделение.
- **Поведение:** генератор создаёт согласованный набор данных: KPI, строки детализации, итоги, отклонения от предыдущего периода. Данные должны быть правдоподобными: суммы неотрицательны, доли в сумме дают 100%, итог равен сумме строк.
- **Детерминированность:** при заданном значении `seed` повторный запуск формирует идентичный набор данных.
- **Объём:** от 10 до 30 строк детализации в зависимости от длины периода; не более 1 000 строк.
- **Поддерживаемые типы отчётов:** продажи, финансы, склад, маркетинг, HR (состав полей — приложение D).

#### 3.1.6 Валидация введённых параметров (F-06)

Проверяется до начала генерации:

- даты заполнены и имеют формат `ДД.ММ.ГГГГ`;
- дата начала не позднее даты окончания;
- период не превышает 366 дней;
- дата окончания не позднее текущей даты;
- тип отчёта выбран из списка;
- длина названия подразделения и автора не превышает 100 символов.

При нарушении выводится сообщение об ошибке рядом с полем или в диалоговом окне; генерация не запускается.

#### 3.1.7 Генерация аналитического текста через ИИ (F-07)

- **Провайдер:** AITunnel, OpenAI-совместимый API.
- **Базовый URL:** `https://api.aitunnel.ru/v1`.
- **Модель:** `deepseek-v4.1-flash-1017` (значение задаётся переменной `AITUNNEL_MODEL`).
- **Авторизация:** заголовок `Authorization: Bearer <AITUNNEL_API_KEY>`.
- **Формат запроса:** Chat Completions, `temperature = 0.3`, `max_tokens = 3000` (модель использует reasoning-токены, поэтому лимит повышен), таймаут 30 секунд.
- **Содержание запроса:** системная инструкция «Ты — аналитик, пиши деловой русский текст без markdown» и пользовательское сообщение с JSON-сводкой отчёта (период, KPI, топ-5 категорий, отклонения).
- **Содержание ответа:** 5–7 предложений: общая динамика, ключевой драйвер роста или падения, риск, рекомендация.
- **Ограничения:** текст не должен содержать вымышленных цифр, отсутствующих в переданных данных.
- **Повторные попытки:** до 2 повторов при кодах 429, 500, 502, 503, 504 и при таймауте; пауза 1 и 2 секунды.
- **Резервный сценарий (fallback):** при недоступности ИИ или превышении лимита попыток формируется шаблонный текст на основе рассчитанных показателей. Генерация отчёта при этом не прерывается.
- **Критерий приёмки:** при отключённом сетевом доступе к AITunnel отчёт формируется полностью, в журнале фиксируется предупреждение, в отчёте используется резервный текст.

#### 3.1.8 Компоновка отчёта (F-08)

Отчёт размещается на отдельном листе. Структура листа приведена в приложении A. Обязательные блоки:

1. заголовок отчёта;
2. подзаголовок с периодом;
3. строка метаданных: подразделение, автор, дата формирования;
4. блок «Ключевые показатели» (5 KPI);
5. блок «Детализация» (таблица данных и строка «Итого»);
6. блок «Аналитический вывод» (текст ИИ или резервный текст);
7. подпись о автоматической генерации;
8. диаграмма (при включённом флаге).

Компоновщик возвращает модель листа: значения ячеек и список запросов форматирования. Модель не зависит от tkinter и может быть протестирована отдельно.

#### 3.1.9 Запись отчёта в Google Таблицу (F-09)

- **Имя листа:** `{Тип}_{ДД.ММ.ГГГГ}_{ДД.ММ.ГГГГ}`. При совпадении имени добавляется суффикс `_2`, `_3` и далее.
- **Порядок записи:**
  1. создание листа;
  2. запись всех значений одним вызовом `values.batchUpdate` (или `values.update` по диапазону);
  3. применение форматирования одним вызовом `batchUpdate`;
  4. добавление диаграммы;
  5. проверка результата чтением контрольного диапазона.
- **Атомарность:** при ошибке на шаге форматирования лист не удаляется, в журнал пишется диагностика; повторный запуск создаёт новый лист с суффиксом.
- **Кэширование:** перед записью модель отчёта сохраняется в `cache/last_report.json` для возможности повторной записи без повторной генерации.

#### 3.1.10 Автоматическое форматирование (F-10)

Обязательные операции форматирования:

| Операция | Требование |
|---|---|
| Объединение ячеек | Заголовок, подзаголовок, названия блоков, текст вывода — на всю ширину таблицы (A:F). |
| Цвета | Палитра: `#1F3864` (тёмно-синий), `#2E75B6` (акцент), `#D9E2F3` (светлая заливка), `#F2F6FC` (чередование строк), `#BFBFBF` (границы). |
| Шрифты | Calibri; заголовок 14 pt полужирный, названия блоков 12 pt полужирный, шапка таблицы 10 pt полужирный, данные 10 pt. |
| Выравнивание | Заголовки и шапка — по центру; текст вывода — по левому краю с переносом; числа — по правому краю. |
| Границы | Тонкие границы `#BFBFBF` вокруг всех ячеек таблицы данных и блока KPI. |
| Ширины столбцов | A — 110 px, B — 190 px, C — 100 px, D — 130 px, E — 120 px, F — 110 px. |
| Высоты строк | Заголовок — 34 px, шапка — 28 px, данные — 20 px, текст вывода — 18 px на строку. |
| Числовые форматы | Суммы — `#,##0.00 ₽`; проценты — `0.0%`; количество — `#,##0`; даты — `dd.mm.yyyy`. |
| Чередование строк | Чётные строки таблицы заливаются `#F2F6FC`. |
| Условное форматирование | Отрицательное отклонение — красный шрифт `#C00000`, положительное — зелёный `#375623`. |
| Закрепление областей | Первые 5 строк закреплены. |
| Перенос текста | Включён для блока аналитического вывода и длинных текстовых ячеек. |

Все операции выполняются пакетно, одним или минимальным числом вызовов `batchUpdate`.

#### 3.1.11 Построение диаграммы (F-11)

- **Тип:** столбчатая диаграмма (COLUMN) по строкам детализации.
- **Категории:** первый столбец таблицы (даты или категории).
- **Ряды:** числовой столбец «Сумма» (или основной числовой показатель типа отчёта).
- **Заголовок:** «Динамика показателя за период».
- **Легенда:** снизу.
- **Размещение:** ячейка H4, размер 600×360 px.
- **Условие:** диаграмма строится только при включённом флаге и наличии не менее двух строк данных.

#### 3.1.12 Журналирование и обработка ошибок (F-12)

- Журнал пишется в `logs/app.log`, ротация при достижении 5 МБ, хранится 3 файла.
- Формат записи: дата и время, уровень, модуль, сообщение.
- Логируются: подключение, создание листа, количество записанных строк, длительность этапов, ошибки API, факт использования fallback.
- Секреты (ключ API, приватный ключ сервисного аккаунта) в журнал не попадают.
- Пользователю показываются сообщения на русском языке без технических стектрейсов; полный стектрейс пишется в журнал.

#### 3.1.13 Выдача ссылки на готовый отчёт (F-13)

После успешной записи приложение формирует URL вида `https://docs.google.com/spreadsheets/d/{SpreadsheetID}/edit#gid={sheetId}` и отображает его в интерфейсе. По клику ссылка открывается в браузере по умолчанию. Ссылка также копируется в буфер обмена по отдельной кнопке.

### 3.2 Нефункциональные требования

Нефункциональные требования определяют, как система должна работать, а не что она должна делать: производительность, надёжность, безопасность, удобство использования и эксплуатационные характеристики.

#### 3.2.1 Требования к надёжности

- **Режим функционирования:** по запросу пользователя (десктопное приложение). Круглосуточный режим не требуется.
- **Время простоя:** не нормируется, так как приложение не является сервисом непрерывного действия.
- **Время восстановления после сбоя:** не более 5 минут — повторный запуск приложения и повторная генерация.
- **Повторные попытки:** при сетевых ошибках и кодах 429/5xx — до 3 повторных попыток с задержкой 1, 2 и 4 секунды.
- **Резервирование данных:** модель последнего отчёта сохраняется в `cache/last_report.json`; исходные данные генерации детерминированы при заданном `seed`.
- **Отказоустойчивость внешних зависимостей:** недоступность AITunnel не блокирует генерацию (fallback); недоступность Google Sheets приводит к понятной ошибке и сохранению модели в кэш.
- **Тестирование и мониторинг:** ведение журнала, самопроверка модуля (F-03), набор модульных тестов для генератора данных и компоновщика.
- **Целостность:** форматирование применяется пакетно; частично оформленный отчёт не считается успешным, факт фиксируется в журнале.

#### 3.2.2 Требования к масштабируемости

- **Объём отчёта:** до 1 000 строк детализации и до 5 000 заполненных ячеек на один отчёт.
- **Количество листов:** до 200 листов в одной таблице (ограничение Google Sheets).
- **Квоты Google API:** до 60 запросов в минуту на пользователя и до 300 запросов в минуту на проект. Приложение обязано обрабатывать превышение квоты повтором с задержкой.
- **Горизонтальное масштабирование:** не применимо, так как ПО является настольным приложением. Серверная инфраструктура, балансировка нагрузки (NGINX, HAProxy) и пул серверов не используются.
- **Многопоточность:** интерфейс не блокируется во время сетевых операций; одновременно допускается одна активная генерация на экземпляр приложения.
- **Расширяемость:** добавление нового типа отчёта выполняется описанием схемы данных и не требует изменения модуля работы с Google Sheets.

| Переменная | Обязательность | Значение по умолчанию | Назначение |
